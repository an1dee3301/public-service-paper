# Documentary coding files

These are preserved coding records, not newly adjudicated estimates. The first-pass automated coder, the second automated coder, and the author's single blind coding are different records; automated agreement does not establish human reliability.

- `terms/`: original codebook, first pass, bounded-excerpt second coding, full-document recoding and adjudication; supplier names are retained as the public-terms audit's subjects.
- `tenders/`: original and revised codebooks, earlier outputs, 109 revised-screen rows and comparison with the author's 20-document sheet. There are 82 relevant revised rows; earlier coding is kept for reconciliation. The tender source table contains 184 document rows but 182 distinct procurement identifiers. Platform brands outside the public-terms audit are replaced with `[platform]`.
- `contracts/`: coded outcomes and eligibility records. Supplier identity fields, contract-object prose and free-text model rationales have been removed from the large panel for privacy. IDs, classifications, financial quantities, dates and outcome flags are retained. The blank/completed human sheets retain bounded contract-object excerpts needed to interpret the author's 50 codes; platform brands are masked.
- `human/`: both original blind templates and completed Coding tabs as CSV, preserving row order, field names and values. Local text paths are reduced to basenames; workbook properties, instructions and time-spent fields are not distributed.
- `comparisons/` and `comparison_readout.md`: preserved counts, confusion matrices and disagreement readouts. Original internal file references in historical readouts may name files not distributed; released inputs are indexed in `../POINTERS.md`.

Full documents, network clients, raw request/response batches and private working records are excluded. Reproducing original automated responses requires the frozen outputs supplied here; no paid or authenticated service is needed to read them. These tables do not establish current contract terms or causal effects.

## Recounting the documentary quantities

Run `python3 coding/reproduce_documentary_counts.py` from the repository root (Python 3, standard library only). The additive tables and script use the eligibility, outcomes and revised tender codes at commit `ebe314c81794dd596c39a0f5442364b5bfb21fa1`. Expected results: provider tags **17 / 183**; classification-confidence sensitivity **21 / 64 = 32.8125%, rounded to 33%**; general-conditions matches among silent revised codes **22 literal / 25 whitespace-normalized**. The script checks unique keys and exact join coverage and calculates each result from rows; it does not substitute printed totals.

- `contracts/provider_tags.csv`: one row for each eligible core contract, joined on `id_contrato`; `provider_tag` is True if any of the case-insensitive expressions in `PROVIDER_PATTERNS` in the script matches the contract object, a space, the process description, a space, and the firm supplier name (missing strings become empty). It is a deterministic administrative-text keyword indicator, distinct from `foreign_platform_v1`, the inherited first-pass dependence classification (25 true among core contracts). The original eight patterns and their subject supplier names are preserved in the script for rule transparency; they do not identify tools used in the research. The public table omits the underlying object, description and supplier-name strings.
- Confidence sensitivity requires no new table. Join `contracts/eligible_contracts.csv` to `contracts/outcomes_v2.csv` by `id_contrato`; retain `elig_core=True`, `atrisk_f12=True`, and `label_conf_v1 >= 0.85` (inclusive); sum `later_12m` and divide by the retained row count. Before the confidence filter the count is 48 / 112. Core eligibility requires a firm, positive value, an AI-product/platform or AI-development-service label, and a signature in the frozen 2023-01-01 to 2026-09-30 window. The outcome window is 365 days from signature, with a full window observed by the frozen 2026-09-30 pull date; later means strictly after the index signature for the same entity and supplier. This recomputes the inherited-label sensitivity, without reclassifying contracts.
- `tenders/general_conditions_matches.csv`: one row for every document with `relevant=True` in `tenders/sa_clauses_v3.csv` (82 rows). Join by `doc`, then retain `T1_variation_control.code=silent` (46 rows). `literal_match` tests whether the exact phrase `general conditions of contract` occurs in the lowercase extracted text. `whitespace_normalized_match` first replaces each maximal whitespace run with one ASCII space (`re.sub(r'\s+', ' ', text.lower())`) and then tests the same phrase; punctuation and OCR errors are not repaired. Each row carries the SHA-256 of the extracted text bytes. The text source is the original extraction if available, otherwise the recovery extraction, decoded as UTF-8 with invalid bytes ignored. The whitespace rule makes explicit the previously reported normalization description; the historical standalone command for that endpoint was not preserved.

The two new tables release frozen search outputs, not third-party full texts or personal fields. They allow public recounting; independently checking the text matches requires the lawfully obtained source extractions with matching hashes. A name match plus a silent code does not establish legal incorporation, absence of a printed provision, or deployment of a provider's service.
